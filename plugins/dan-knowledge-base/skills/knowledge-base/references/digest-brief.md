# What a digest keeps

The knowledge-base half of a covered gate's brief. The gate's own instructions
say what a digest must leave out; this says what a knowledge base needs a digest
to keep, so that notes can be written from it without the raw text.

Keep, from every source:

- **Decisions, with their reasons** — what was decided, and why.
- **How a system or process works** — mechanics, rules, steps, limits.
- **Dated events** — what happened, and when.
- **Commitments, with their owners** — named by business role, not as people.
- **Open questions** — what is undecided, and who is deciding it, by role.
- **Where each item came from** — the source's ids, timestamps and links, so a
  note can cite the message, meeting or page it rests on.

Quote only short phrases, where the exact wording matters; everything else is
paraphrase.

By source kind:

- **Chat** — organised per conversation, then per thread, each item carrying the
  message timestamp it comes from.
- **A meeting** — decisions and action items first, then the discussion that
  matters. Read the transcript, not only the recap: the recap misses much of it.
- **A wiki page** — what changed since the watermark, not what the page says
  overall, with the page id and edit time.
